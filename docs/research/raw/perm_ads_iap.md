# Current versions and Android/iOS setup gotchas for permission_handler, google_mobile_ads, and in_app_purchase (Flutter) for GeoWake — verified July 2026

## Summary
As of 2026-07-18, the current versions are: permission_handler 12.0.3 (pulls permission_handler_android 13.x, which forces compileSdk 35 + Java 17), google_mobile_ads 9.0.0 (bundles GMA Android SDK 25.3.0 / iOS 13.3.0 / UMP 4.0.0-Android, and requires Flutter >= 3.38.1 / Dart >= 3.10.0), and in_app_purchase 3.3.0 (pulls in_app_purchase_android 0.5.1, which bundles Google Play Billing Library 8.0.0). The single most important, time-sensitive item for GeoWake: Google Play turns down Billing Library 7 on 2026-08-31 — every new app AND every app update must ship Billing Library 8+ after that date, so you MUST be on in_app_purchase_android >= 0.5.0 (i.e. in_app_purchase >= 3.x); older in_app_purchase releases (Billing 6/7) will be rejected at upload. For ads, the AndroidManifest APPLICATION_ID meta-data (Android) and GADApplicationIdentifier Info.plist key (iOS) are mandatory — the app crashes at launch if either is missing. UMP is Google's consent SDK: you must call requestConsentInfoUpdate() every launch and check canRequestAds() before loading any ad; it is contractually required for EEA/UK/Switzerland, but there is currently no AdMob UMP mandate specific to India — India's DPDP consent-manager rules only take effect around Nov 2026 / May 2027. Since GeoWake is Android-first, iOS ATT/SKAdNetwork is lower priority but still crash-relevant if you ship iOS with ads.

## Caveats
- GeoWake-specific: as a background-location wake-alarm you will also need Android 14+ foreground-service-type declarations (e.g. android:foregroundServiceType="location") and the matching FOREGROUND_SERVICE_LOCATION permission, plus USE_EXACT_ALARM (auto-granted) or SCHEDULE_EXACT_ALARM (user-revocable) — these are enforced by targetSdk, NOT by permission_handler itself; permission_handler only surfaces Permission.scheduleExactAlarm status. Verify your foreground-service manifest separately.
- Published-date figures are relative ('~38/44/46 days ago') as shown on pub.dev on 2026-07-18; treat the version numbers as authoritative and the exact release dates as approximate.
- google_mobile_ads 9.0.0's bump to Flutter >= 3.38.1 / Dart >= 3.10.0 (introduced in v8) may force a Flutter SDK upgrade before you can adopt it — check your CI/toolchain pinning first.
- The India DPDP timeline dates (consent-manager ~2026-11-13, substantive ~2027-05-13) come from legal/press reporting, not a single primary government gazette I fetched — confirm exact dates with counsel before relying on them for a compliance decision.
- iOS setup details (ATT/SKAdNetwork/StoreKit) are included for completeness, but GeoWake is Android-first; none of the iOS items block an Android-only release.
- I could not fetch the plugin GitHub READMEs directly (404/thin content); Android compileSdk/AGP specifics for google_mobile_ads were not pinned this session beyond the Flutter 3.38.1 floor — if a build fails on compileSdk, note that the co-installed permission_handler_android 13 already forces compileSdk 35, which typically satisfies GMA 25.x.
